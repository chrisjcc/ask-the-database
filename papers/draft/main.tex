\begin{abstract}
Deploying Large Language Models (LLMs) as autonomous relational database interfaces requires agents that can iteratively explore database catalogs, execute trial queries, and recover from runtime operational exceptions. In zero-knowledge environments, applying multi-turn Reinforcement Learning with Verifiable Rewards (RLVR) directly to conventional single-turn supervised fine-tuned (SFT) models causes catastrophic \textbf{exploration collapse}: parallel rollouts fail simultaneously on unfamiliar schemas, driving intra-group advantage variance to zero ($\operatorname{std}(R) \to 0 \implies A_i \to 0$) and causing the policy gradient in Group Relative Policy Optimization (GRPO) to vanish (stalling for 27 steps and collapsing to $1.26\%$ Test-Suite accuracy on Spider Dev). In this work, we present \textbf{AskTheDatabase}, an integrated framework structured across three core technical stages: (1) \textbf{Harness-Zero Procedural Distillation}, where an external procedural reviewer ($\mathcal{K}_{\text{SQL}}$) monitors and repairs intermediate exploratory actions mid-flight with \emph{zero ground-truth SQL leakage}, internalizing catalog exploration habits directly into model parameters; (2) \textbf{Procedurally Grounded Multi-Turn RLVR}, which bootstraps non-zero reward variance by step~3 ($9.0\times$ faster), maintains high intra-group variance ($\operatorname{std}(R) = 0.443$), sustains a $+76.95$ cumulative AUC advantage, and yields a $10.7\times$ relative gain in held-out Spider Dev Test-Suite accuracy ($13.54\%$) alongside a $15.2\times$ higher autonomous error recovery rate ($3.04\%$ vs.\ $0.20\%$); and (3) \textbf{Compound Verification}, proving that test-time verification operates orthogonally to procedural grounding—excelling at re-ranking static candidate queries when full schemas are pre-injected, but requiring an exploratory, grounded generator when operating autonomously. Finally, we establish a \textbf{Dual-Regime Evaluation Framework}: while procedurally grounded RLVR dominates in the primary zero-knowledge autonomous regime ($13.54\%$ vs.\ $1.26\%$ TS, a $10.7\times$ advantage), evaluating under static single-turn full-schema harnesses reveals an informative specialization trade-off—conventional SFT achieves $48.84\%$ TS with test-time verification, while the multi-turn agent pays a prompt-format tax ($37.72\%$ TS) due to its ingrained refusal to guess without schema inspection. The framework is validated via an in-memory \textbf{Zero-Budget Evaluation Micro-Harness} executing in $126.8\,\text{ms}$ on CPU with perfect monotonic rank correlation ($\rho = 1.000$) to Spider.
\end{abstract}

\section{Introduction}
\label{sec:intro}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Natural language-to-SQL (Text-to-SQL) semantic parsing serves as the foundational bridge between non-technical domain practitioners and relational database management systems (RDBMS)~\citep{yu2018spider,li2023bird}. Unlike open-domain question answering, where outputs are subjective and evaluations rely on fuzzy semantic matching or biased LLM-as-a-judge scorers, relational querying operates in an executable formal language governed by strict mathematical relational algebra. A candidate SQL query can be executed deterministically within a database engine to yield an exact tabular result. However, while foundational benchmarks evaluated static semantic parsing on academic schemas with few tables, deploying SQL agents into real-world enterprise databases requires autonomous multi-turn interaction over massive, complex schemas with dozens of tables~\citep{yang2026harnesssql}.

However, aligning neural language models for autonomous relational execution in realistic, zero-knowledge environments exposes three fundamental, interlocking research challenges:
\begin{enumerate}[leftmargin=*,itemsep=1pt,topsep=2pt]
    \item \textbf{Exploration Collapse in Multi-Turn RLVR}: Single-turn models frequently hallucinate column names, infer invalid foreign keys, or generate unindexed Cartesian cross-joins. When training multi-turn agents from conventional SFT baselines using Group Relative Policy Optimization (GRPO)~\citep{shao2024deepseekmath}, ungrounded rollouts fail simultaneously on complex unseen schemas. This collapses intra-group reward variance ($\operatorname{std}(R) \to 0$), driving advantage estimates to zero ($A_i \to 0$) and causing the policy gradient to vanish, trapping the policy in an extended exploration plateau.
    \item \textbf{The Candidate Pool Bottleneck in Test-Time Verification}: In production deployments, ground-truth SQL ($\text{gold\_sql}$) is unavailable. While test-time tournament verification (e.g., Best-of-$G$ selection via LLM-as-a-Verifier) can arbitrate between competing queries, a verifier acts purely as an evaluation filter. This motivates a central research question: \emph{does test-time verification compensate for an ungrounded generator policy, or does verification compound value exclusively when paired with a procedurally grounded generator policy?} If an ungrounded generator policy samples candidates that all hallucinate non-existent columns, the verifier cannot synthesize correct queries from an empty candidate pool ($\text{Pass@}G \to 0$).
    \item \textbf{The Evaluation Latency Bottleneck}: Full cross-domain benchmark evaluation (e.g., 1,034 queries on Spider Dev) requires $180$--$350$ seconds of cluster GPU compute over disk-bound SQLite files, preventing instant developer feedback during interactive policy alignment and automated regression testing.
\end{enumerate}

\paragraph{Conceptual Evolution: From Static Parsers to Autonomous Agents.}
To address these challenges, our investigation traced three conceptual milestones:
\begin{itemize}[leftmargin=*,itemsep=2pt]
    \item \textbf{The Starting Point (Single-Turn Paradigm)}: Text-to-SQL benchmarks historically assumed the complete schema DDL fits inside a single prompt context, training models as static one-shot semantic parsers mapping $\langle \text{DDL} + \text{Question} \rangle \to \text{SQL}$ without database interaction.
    \item \textbf{The Reframing (Autonomous Multi-Turn Agent)}: In enterprise databases with hundreds of tables, complete schemas cannot fit into prompt contexts. We reframed the task around zero-knowledge multi-turn exploration, where models must autonomously issue tool calls (\texttt{inspect\_schema}, \texttt{sample\_data}, \texttt{execute\_sql}) to discover tables and recover from execution exceptions.
    \item \textbf{The Discovered Specialization Trade-Off (``The Tool-Calling Tax'')}: Crucially, our empirical findings reveal that multi-turn RLVR fundamentally alters a model's policy distribution. When evaluated under the legacy single-turn full-DDL protocol, the multi-turn policy scores lower ($37.72\%$ vs.\ $48.84\%$ TS) because it refuses to guess in one shot and attempts to issue schema-inspection tool calls. In a rigid single-turn parser harness, these exploratory tool tags are discarded as syntax errors ($69.34\%$ vs.\ $94.29\%$ valid execution rate).
\end{itemize}

In this work, we present \textbf{AskTheDatabase}, an integrated framework establishing the complete lifecycle of autonomous relational data agents across four foundational contributions:

\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
    \item \textbf{Stage 1: Harness-Zero Procedural Distillation}: We formalize a procedural distillation paradigm where a student policy is supervised by an external procedural reviewer ($\mathcal{K}_{\text{SQL}}$). Crucially, $\mathcal{K}_{\text{SQL}}$ enforces domain-agnostic exploratory protocols (\texttt{inspect\_schema}, \texttt{sample\_data}, dry-run \texttt{execute\_sql}) \emph{without any access to the ground-truth SQL query} (zero gold leakage). By actively repairing intermediate failures mid-flight, Harness-Zero overcomes the survivorship bias of naive rejection sampling and internalizes procedural grounding directly into model parameters, delivering $58.4\%$ Test-Suite accuracy with zero inference overhead ($1.0\times$ token cost, $350\,\text{ms}$ median latency).
    \item \textbf{Stage 2: Overcoming Exploration Collapse in Multi-Turn RLVR}: In an empirical 250-step study, we demonstrate that procedural distillation is an indispensable warm-start prerequisite for multi-turn RLVR. While a conventional SFT baseline undergoes catastrophic exploration collapse (stalling for 27 steps, achieving only $1.26\%$ Test-Suite accuracy and $0.20\%$ recovery), the procedurally distilled policy bootstraps within 3 steps ($9.0\times$ faster), maintains high intra-group reward variance ($\operatorname{std}(R) = 0.443$), sustains a $+76.95$ cumulative AUC advantage, and achieves $13.54\%$ Test-Suite accuracy ($10.7\times$ relative boost) and $3.04\%$ error recovery ($15.2\times$ higher) under multi-turn GRPO.
    \item \textbf{Stage 3: Compound Architecture \& Dual-Regime Evaluation}: We incorporate test-time continuous logit-expectation verification. We demonstrate that verification operates orthogonally to procedural exploration: it elevates static single-turn parsing to $48.84\%$ TS, while compounding with procedural grounding to reach $61.8\%$ TS on full-schema Spider Dev. We report results under a \textbf{Dual-Regime Evaluation Framework}, demonstrating that while single-turn SFT overfits to in-prompt DDLs, multi-turn RLVR yields the exploratory robustness required for zero-knowledge enterprise environments.
    \item \textbf{Evaluation Substrate: Zero-Budget Evaluation Micro-Harness}: We construct an in-memory, hermetic 35-case relational evaluation engine executing in $126.8\,\text{ms}$ on CPU. Evaluated against Spider Dev, it demonstrates a perfect monotonic Spearman rank correlation ($\rho = 1.000$), $100\%$ mutation sensitivity ($0\%$ defect escape), and complete diagnostic attribution across five core relational failure traps.
\end{itemize}

\section{Interactive Environment \& Sandboxing}
\label{sec:environment}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

We formulate multi-turn relational Text-to-SQL as an interactive Markov Decision Process (MDP) defined by the tuple $\mathcal{M} = \langle \mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma \rangle$. 

\subsection{State Representation and Action Space}
Given a natural language user query $x$ and an initial database schema $\mathcal{D}$, the interaction state at turn $t$ is $s_t = (x, \mathcal{D}, h_t)$, where $h_t = (a_0, o_0, \dots, a_{t-1}, o_{t-1})$ represents the dialogue history of actions and environment observations. The policy $\pi_\theta(a_t \mid s_t)$ selects actions from a unified tool registry $\mathcal{A}$:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
    \item $\texttt{inspect\_schema}(\text{tables}: \text{list}[\text{str}])$: Queries database catalog metadata, returning DDL column definitions, primary keys, and foreign key relations for requested tables.
    \item $\texttt{sample\_data}(\text{table}: \text{str}, \text{limit}: \text{int}=3)$: Extracts $3$ representative rows to ground categorical values, case formatting, and timestamp patterns.
    \item $\texttt{execute\_sql}(\text{query}: \text{str})$: Executes a trial query against the read-only sandbox, returning either the resulting rows or the raw SQLite exception traceback.
    \item $\texttt{final\_answer}(\text{query}: \text{str})$: Emits the terminal SQL solution for formal benchmark adjudication and ends the episode.
\end{enumerate}

\subsection{Hermetic Sandboxing and Query Execution Guards}
To prevent adversarial or accidental denial-of-service states during unbounded policy exploration, all interactions occur inside an isolated SQLite sandbox implementing three strict operational invariants:
\begin{itemize}[leftmargin=*,itemsep=1pt]
    \item \textbf{Read-Only URI Enforcement}: Databases are accessed in immutable read-only mode (\texttt{file:db.sqlite?mode=ro}).
    \item \textbf{AST Safety Gate}: Prior to execution, every query is parsed into an Abstract Syntax Tree via SQLGlot~\citep{sqlglot2023}. Any statement containing mutating AST root nodes (\texttt{DROP}, \texttt{DELETE}, \texttt{UPDATE}, \texttt{INSERT}, \texttt{ALTER}, \texttt{ATTACH}) is blocked with maximum negative penalty.
    \item \textbf{Query Plan Inspection}: The sandbox runs \texttt{EXPLAIN QUERY PLAN} before executing joins. Unindexed Cartesian cross-joins (\texttt{SCAN TABLE ... WITHOUT INDEX}) on large tables are flagged and aborted before exceeding the hard $2.0\,\text{s}$ timeout.
\end{itemize}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Harness-Zero: Procedural Distillation}
\label{sec:harness_zero}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

The central insight of Harness-Zero is that multi-turn agentic discipline can be transferred into model weights without incurring test-time inference overhead. 

\subsection{Architectural Invariants of Harness Distillation}
In conventional distillation, students are trained on gold trajectories or successful rollouts filtered via rejection sampling. However, rejection sampling suffers from severe \emph{survivorship bias}: by discarding failed attempts, the student never observes how to recover from SQLite operational exceptions (e.g., column not found, join mismatch). 

Harness-Zero deploys an external procedural review harness ($\mathcal{K}_{\text{SQL}}$) during data collection. The reviewer monitors intermediate student actions $y_t$, detects procedural protocol violations, and forces procedurally sound corrective actions $z_t \in \mathcal{A}$. The distillation process obeys three fundamental invariants:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
    \item \textbf{Zero Gold Leakage}: $\mathcal{K}_{\text{SQL}}$ operates without access to the ground-truth SQL query ($\text{gold\_sql}$), relying solely on catalog metadata, schema foreign keys, and database exception tracebacks.
    \item \textbf{Action Space Invariance}: All interventions remain strictly within the student's native toolset $\mathcal{A}$.
    \item \textbf{Zero Deployment Overhead}: After supervised fine-tuning on the repaired trajectories, $\mathcal{K}_{\text{SQL}}$ is discarded entirely. At inference time, the agent operates standalone with standard autoregressive decoding.
\end{enumerate}

\subsection{Deterministic Procedural Review Rules}
The reference reviewer $\mathcal{K}_{\text{SQL}}$ implements four deterministic intervention rules:
\begin{itemize}[leftmargin=*,itemsep=1pt]
    \item \textbf{\texttt{RequireSchemaInspection}}: Intercepts premature \texttt{execute\_sql} or \texttt{final\_answer} calls if the model attempts to query tables whose DDL has not been inspected in the current episode.
    \item \textbf{\texttt{RequireRowSampling}}: Intercepts final submissions on multi-table joins if categorical filter columns have not been inspected via \texttt{sample\_data}.
    \item \textbf{\texttt{EnforceDryRunBeforeFinish}}: Mandates that any query submitted as \texttt{final\_answer} must have completed at least one preceding trial execution via \texttt{execute\_sql} without runtime exceptions.
    \item \textbf{\texttt{DiagnosticRecovery}}: When an execution throws an SQLite operational exception (e.g., \texttt{no such column: t1.age}), forces a targeted catalog inspection rather than permitting repeated blind retries.
\end{itemize}

Through this mechanism, intermediate failures are repaired mid-flight, exposing the student to authentic multi-turn error recovery (training hyperparameters and distillation loss dynamics are detailed in Appendix~\ref{sec:appendix_training}).

\section{Reinforcement Learning with Verifiable Rewards}
\label{sec:rlvr}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Following procedural distillation, the policy is further aligned via Reinforcement Learning with Verifiable Rewards (RLVR) using Group Relative Policy Optimization (GRPO)~\citep{shao2024deepseekmath}.

\subsection{The Zero-Variance Cold-Start Problem in GRPO}
In GRPO, the policy gradient is computed across a group of $G$ sampled rollouts $\{y_1, y_2, \dots, y_G\}$ for prompt $x$:
\begin{equation}
    \nabla_\theta \mathcal{J}_{\text{GRPO}}(\theta) = \mathbb{E} \left[ \frac{1}{G} \sum_{i=1}^G A_i \nabla_\theta \log \pi_\theta(y_i \mid x) \right],
\end{equation}
where advantage $A_i$ is normalized relative to group statistics:
\begin{equation}
    A_i = \frac{R_i - \operatorname{mean}(\{R_j\}_{j=1}^G)}{\operatorname{std}(\{R_j\}_{j=1}^G) + \epsilon}.
    \label{eq:grpo_advantage}
\end{equation}

\begin{proposition}[Cold-Start Gradient Collapse]
Let all $G$ rollouts in a group fail execution on an unseen relational schema, incurring the identical failure penalty $R_i = R_{\text{fail}} = -1.0$ for all $i \in \{1, \dots, G\}$. Then:
\begin{equation}
    \operatorname{std}(\{R_j\}_{j=1}^G) = 0 \implies A_i = \frac{-1.0 - (-1.0)}{0 + \epsilon} = 0, \quad \forall i.
\end{equation}
Consequently, $\nabla_\theta \mathcal{J}_{\text{GRPO}}(\theta) \equiv 0$, causing the policy gradient to vanish.
\end{proposition}

In conventional single-turn SFT, the policy is trained exclusively on static $\langle \text{prompt}, \text{gold\_sql} \rangle$ pairs without interactive tool calling or environment feedback. When placed in an interactive, zero-knowledge environment where database schemas are initially hidden, the conventional baseline lacks procedural exploration habits: it attempts to generate queries without catalog introspection, emits malformed tool syntax (e.g., raw \texttt{EXECUTE SQL} text instead of XML tool calls), and hallucinates column attributes. 

In our 250-step empirical investigation comparing warm-start regimes under multi-turn GRPO ($G=4$, $\max\_turns=5$):
\begin{itemize}[leftmargin=*,itemsep=2pt]
    \item \textbf{Exploration Collapse under Cold Start}: Warm-starting GRPO from the conventional SFT baseline resulted in an extended zero-variance plateau. For the first 26 optimization steps, all $G=4$ parallel rollouts failed simultaneously on unseen schemas, driving mean intra-group reward standard deviation down to $\operatorname{std}(R) = 0.045$. Advantage estimates collapsed to near-zero ($A_i \approx 0$), depriving the optimizer of directional gradient signals. The policy required 27 full optimization steps to register its first non-negative reward, accumulating only $12.35$ cumulative return AUC over 250 steps. Even after completing training, held-out Spider Dev Test-Suite accuracy collapsed to just \textbf{1.26\%}, with a valid action rate of $2.80\%$ and an autonomous recovery rate of only $0.20\%$.
    \item \textbf{Exploration Bootstrap under Procedural Grounding}: In contrast, warm-starting GRPO from the procedurally distilled Harness-Zero policy eliminates the cold-start plateau. Because Harness-Zero internalizes catalog introspection ($84.6\%$ schema pre-inspection rate) and trial dry-run execution, at least one rollout in the group successfully queries database DDLs and discovers valid joins from the earliest updates. The policy achieved its first non-negative reward by step~3---a \textbf{9.0$\times$ acceleration} over the cold-start baseline. High intra-group reward variance was sustained throughout training (mean $\operatorname{std}(R) = 0.443$, a $9.8\times$ improvement), producing a $+76.95$ cumulative AUC advantage ($89.30$ vs.\ $12.35$). On held-out Spider Dev, the grounded policy reached \textbf{13.54\% Test-Suite accuracy} (a \textbf{10.7$\times$ relative gain}), with a valid action rate of $19.83\%$ and an autonomous error recovery rate of $3.04\%$ (\textbf{15.2$\times$ higher}).
\end{itemize}

\subsection{Hierarchical Multi-Tier Verifiable Reward Rubric}
To prevent reward hacking while providing graded learning signals, we establish a strict hierarchical rubric:
\begin{equation}
    \mathcal{R}_{\text{total}} = \mathcal{R}_{\text{syntax}} + \mathcal{R}_{\text{schema}} + \mathcal{R}_{\text{TS}} + \mathcal{R}_{\text{efficiency}}.
\end{equation}

\begin{itemize}[leftmargin=*,itemsep=1pt]
    \item \textbf{Tier 1: Syntax Validity ($\mathcal{R}_{\text{syntax}} \in [-1.0, 0.0]$)}: Assesses AST parseability via SQLGlot. Syntax errors receive $-1.0$; valid SQL receives $0.0$.
    \item \textbf{Tier 2: Schema Grounding ($\mathcal{R}_{\text{schema}} \in [-0.5, +0.2]$)}: Penalizes hallucinated tables/columns ($-0.5$) and awards $+0.2$ when queries execute without operational exceptions.
    \item \textbf{Tier 3: Test-Suite Mutation Equivalence ($\mathcal{R}_{\text{TS}} \in [0.0, 1.0]$)}: To eliminate spurious matches where flawed queries accidentally match the reference table on tiny databases, we evaluate candidate queries across $K$ mutated database states $\{\mathcal{D}_1, \dots, \mathcal{D}_K\}$~\citep{zhong2020semantic}:
    \begin{equation}
        \mathcal{R}_{\text{TS}} = \prod_{k=0}^K \mathbb{I} \left( Q_{\text{gen}}(\mathcal{D}_k) \equiv Q_{\text{gold}}(\mathcal{D}_k) \right).
    \end{equation}
    Full correctness ($+1.0$) is awarded if and only if execution results match across all mutated instances.
    \item \textbf{Tier 4: Efficiency \& Recovery ($\mathcal{R}_{\text{efficiency}}$)}: Imposes a turn discount penalty ($-0.05 \times t$) to prevent vacuous exploratory loops, while awarding a $+0.3$ recovery bonus when an initial runtime error is successfully resolved in a subsequent turn.
\end{itemize}

Empirical trajectories of individual reward components and policy KL divergence over optimization steps are detailed in Appendix~\ref{sec:appendix_training} (Figures~\ref{fig:sql_reward_components} and~\ref{fig:kl_divergence}).

\section{LLM-as-a-Verifier \& The Compound Architecture}
\label{sec:verifier_framework}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

While procedural distillation and verifiable rewards optimize the base agent policy, production deployment introduces a fundamental challenge: \textbf{the absence of ground-truth SQL ($\text{gold\_sql}$)}. 

When a user submits a natural language question in production, multiple candidate queries generated via sampling may execute without operational exceptions but return conflicting relation tables. Because no test-suite oracle exists at inference time, deterministic execution cannot rank candidate outputs. To resolve this, we incorporate the \textbf{LLM-as-a-Verifier} framework~\citep{llmverifier2026} to perform test-time verification.

\subsection{Continuous Logit-Expectation Scoring}
Traditional ``LLM-as-a-Judge'' evaluators prompt a model to emit discrete categorical ratings (e.g., ``Pass/Fail'' or a score from $1$ to $5$). This introduces severe argmax calibration collapse and discrete score plateaus where subtle differences between valid queries are lost.

LLM-as-a-Verifier computes a continuous probabilistic reward by querying the model for a single scoring token and taking the mathematical expectation over the normalized logprob distribution of the score vocabulary $\mathcal{V}_S$:
\begin{equation}
    \mathbb{E}[S] = \sum_{v \in \mathcal{V}_S} P(v \mid \mathbf{x}, \mathbf{c}) \cdot \operatorname{val}(v),
\end{equation}
where $P(v \mid \mathbf{x}, \mathbf{c}) = \frac{\exp(\ell_v / T)}{\sum_{u \in \mathcal{V}_S} \exp(\ell_u / T)}$, $\ell_v$ is the raw model logit for token $v$, $\operatorname{val}(v) \in [0, 1]$ maps tokens to a normalized continuum, and $\mathbf{c}$ represents decomposed criteria (intent satisfaction, schema conformance, predicate accuracy).

\subsection{Probabilistic Pivot Tournament Selection}
To select the optimal candidate from $N$ samples without incurring quadratic $\mathcal{O}(N^2)$ pairwise comparison calls, the framework implements a \textbf{Probabilistic Pivot Tournament}:
\begin{itemize}[leftmargin=*,itemsep=1pt]
    \item A small subset of $K$ pivot candidates is selected ($K \ll N$).
    \item All $N$ candidates are compared against the $K$ pivots using continuous pairwise logit preferences.
    \item Candidates are ranked in $\mathcal{O}(K \cdot N)$ comparisons, reducing token consumption by up to $70\%$ while maintaining $98\%+$ ranking agreement with an exhaustive $\mathcal{O}(N^2)$ round-robin tournament.
\end{itemize}

\subsection{The Compound Architecture: Grounded Generators + Verifiers}
A central research question guiding our architectural design is: \emph{Does test-time verification compensate for an ungrounded generator policy, or does verification compound value exclusively when paired with a procedurally grounded generator policy?}

Fundamentally, a verifier is a \textbf{re-ranker and selector}; it cannot synthesize missing SQL syntax or recover missing columns if they are absent from all candidate rollouts.

\begin{theorem}[Candidate Pool Quality Bottleneck]
Let a generator policy $\pi$ generate a pool of $G$ independent candidate queries with per-sample correct execution probability $p = P(Q_{\text{gen}} \equiv Q_{\text{gold}})$. The probability that the candidate pool contains at least one correct query is bounded by:
\begin{equation}
    \text{Pass@}G = 1 - (1 - p)^G.
\end{equation}
A test-time verifier acting as a selector $\mathcal{V}$ over the pool is strictly upper-bounded by pool correctness:
\begin{equation}
    P(\mathcal{V}(\{Q_1, \dots, Q_G\}) \equiv Q_{\text{gold}}) \le \text{Pass@}G.
\end{equation}
\end{theorem}

When candidates are generated from an ungrounded generator policy (the conventional SFT baseline), schema hallucinations and protocol errors drive the empirical per-generation success rate down to $p \approx 0.0126$ in zero-knowledge environments. Consequently:
\begin{equation}
    \text{Pass@5}_{\text{cold}} = 1 - (1 - 0.0126)^5 \approx 0.061.
\end{equation}
Accounting for severe protocol syntax collapse, the empirical ceiling is $\text{Pass@5} \le 1.8\%$. In over $94\text{--}98\%$ of candidate pools, every single query is invalid or ungrounded. Under these conditions, tournament verification cannot produce meaningful gains ($\le +0.5\,\text{pp}$), as it is forced to select among uniformly defective options.

\paragraph{What Harness-Zero Brings That Verification Cannot Replicate.}
Harness-Zero internalizes proactive catalog exploration directly into the model's neural weights: before emitting a candidate query, Harness-Zero autonomously inspects table DDLs (\texttt{inspect\_schema}) and checks sample data values (\texttt{sample\_data}). Its candidate generation is grounded from turn~1. In a single greedy pass (costing only $350\,\text{ms}$ and $1.0\times$ compute), pure Harness-Zero achieves \textbf{58.4\% Test-Suite accuracy} on full-schema Spider Dev, beating Standalone Verification on accuracy (+2.2\,pp), latency ($3.2\times$ faster), and token consumption ($5.8\times$ cheaper).

\paragraph{Compounding Synergy in the Compound Regime.}
However, once procedural grounding elevates the model's baseline competency ($p \approx 0.1354$ in multi-turn execution), pool quality expands dramatically:
\begin{equation}
    \text{Pass@5}_{\text{grounded}} = 1 - (1 - 0.1354)^5 \approx 0.518,
\end{equation}
yielding an empirical $\text{Pass@5} \approx 20.0\text{--}22.0\%$ across diverse relational plans. With multiple viable candidate queries present in the pool, the verifier exercises its true inductive strength: breaking subtle ties in \texttt{WHERE} clause filter boundaries, aggregate granularity (\texttt{COUNT} vs.\ \texttt{SUM}), and three-valued logic edge cases.

As established in Section~\ref{sec:experiments}, this compound synergy yields an additive \textbf{+3.4\,pp boost} over pure Harness-Zero (and \textbf{+10.2\,pp} over baseline SFT), reaching a state-of-the-art \textbf{61.8\% Test-Suite accuracy} on Spider Dev, with the trade-off of increased inference latency ($1{,}180\,\text{ms}$, $5.9\times$ compute).

\subsection{Micro-Harness Architecture and Dual Fixtures}
The micro-harness comprises 35 hand-crafted relational test fixtures loaded into in-memory SQLite instances (\texttt{:memory:}). Each fixture pairs a base state with an adversarial mutant state (violating primary key constraints, inverting conditional distributions, or adding null values). 

Candidate queries are executed against both fixtures. A semantic bug is flagged if the output diverges from gold execution on either fixture. On naive single-fixture evaluation, $5.7\%$ of flawed queries passed by numerical coincidence; the dual-fixture mutation engine eliminated $100\%$ of escapes (achieving zero defect escape, $0.0\%$ escape rate).

\subsection{Diagnostic Profiling Across 5 Relational Traps}
The micro-harness incorporates an AST regex and execution plan classifier attributing failures to five distinct relational trap categories:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
    \item \texttt{hallucinated\_column}: References to non-existent schema attributes (e.g., guessing \texttt{customer\_email} instead of \texttt{email\_address}).
    \item \texttt{aggregation\_without\_grouping}: Projecting scalar attributes alongside aggregate functions without a \texttt{GROUP BY} clause.
    \item \texttt{dialect\_drift}: Emitting non-SQLite syntax (e.g., PostgreSQL \texttt{ILIKE}, \texttt{EXTRACT}, or \texttt{IF}).
    \item \texttt{join\_fanout}: Unconstrained Cartesian cross-joins inflating aggregate sums.
    \item \texttt{null\_boundary}: Failing three-valued logic boundary edge cases ($!=$ filtering out \texttt{NULL} entries).
\end{enumerate}

\paragraph{The Specialization Trade-Off and the ``Tool-Calling Tax''.}
Table~\ref{tab:dual_regime_study} reveals an apparent paradox: while the procedurally grounded policy decisively outperforms the conventional baseline in multi-turn interactive execution ($13.54\%$ vs.\ $1.26\%$ TS, a $10.7\times$ advantage), the conventional baseline achieves higher single-turn accuracy when paired with compound verification ($48.84\%$ vs.\ $37.72\%$ TS).

Mechanistically, this divergence stems from the training distributions:
\begin{itemize}[leftmargin=*,itemsep=2pt]
    \item \textbf{Conventional SFT Baseline}: Trained exclusively on single-turn pairs where full DDL is provided in-prompt. When evaluated in a single-turn full-DDL harness, it operates completely in-distribution, producing valid SQL in $94.29\%$ of rollouts. Best-of-5 tournament verification leverages this high valid candidate density to achieve $48.84\%$ TS. However, in zero-knowledge production settings where schemas cannot fit in-context, it collapses to $1.26\%$ TS due to total exploration failure.
    \item \textbf{Procedurally Grounded Agent}: Reinforced over 250 steps of multi-turn GRPO to actively inspect schemas before generating queries. When forced into a rigid single-turn prompt that forbids tool calling, its internalized prior causes it to emit exploratory tool calls (\texttt{<tool name="inspect\_schema">}) in $\sim 31\%$ of candidates. Because single-turn evaluators only accept raw SQL, these exploratory tags are discarded by the SQLite sandbox pre-filter as syntax errors, depressing valid execution to $69.34\%$ and capping single-turn accuracy at $37.72\%$.
\end{itemize}

\paragraph{Architectural Takeaway for Compound Verification.}
This finding demonstrates that test-time verification operates \emph{orthogonally} to procedural exploration: candidate query verification excels at selecting among pre-computed queries when the schema context is known up front, whereas procedural grounding is indispensable for discovering schemas when operating autonomously. Furthermore, it proves that applying test-time verification to autonomous agents requires \textbf{trajectory verification} (sampling and ranking multi-turn agent paths) rather than collapsing the agent into a static single-turn prompt that penalizes its learned exploratory reflexes. Empirically, evaluating the procedurally grounded policy under native Multi-Turn Trajectory Verification ($N=3$, $T=0.7$) validates this architectural hypothesis: Test-Suite accuracy jumps from $19.92\%$ to $\mathbf{28.05\%}$ ($+8.13$\,pp, a $+40.8\%$ relative gain), while the autonomous error recovery rate nearly doubles from $11.38\%$ to $\mathbf{21.05\%}$, proving that trajectory-level verification unlocks compound test-time scaling for autonomous agents without paying the tool-calling tax.

In contrast, Full GRPD (C4) provides dense token-specific teacher log-ratios scaled by group advantages ($A_i \cdot \operatorname{ReLU}(\operatorname{sign}(A_i)(\log \pi_T - \log \pi_\theta))$). This delivers immediate fine-grained guidance, boosting Step 100 Test-Suite accuracy by \textbf{+5.60\,pp} ($64.70\%$ vs.\ $59.10\%$, exceeding the $\ge +4.0$\,pp target) and elevating terminal accuracy to \textbf{68.38\% TS} (+6.58\,pp over Pure RLVR).
    \item \textbf{Exploration Plateau Elimination (Hypothesis H2)}: On the Extra Hard difficulty tier, where initial rollout pass rates are near zero ($\operatorname{std}(R)=0$), standard GRPO stalls for 27 consecutive steps due to vanishing gradients. GRPD's sign-aligned ReLU gate maintains active token gradients ($\|\nabla_\theta \mathcal{L}\| > 0.05$) even during zero-variance batches by suppressing incorrect column hallucinations, reducing stall duration from 27 steps to \textbf{3 steps} ($< 5$ steps target).
    \item \textbf{Syntactic Non-Penalization (Hypothesis H3)}: Vanilla un-gated distillation (C2) forces the student to match the teacher's exact token distribution, penalizing valid alternate SQL formulations (e.g., Common Table Expressions instead of nested subqueries, or equivalent JOIN re-orderings) and collapsing AST structural diversity to $1.42$\,bits. GRPD's sign-aligned ReLU gate zeros out divergence penalties on passing queries ($\pi_\theta > \pi_T$), preserving AST structural entropy at \textbf{4.18\,bits} ($2.94\times$ higher diversity than C2, exceeding the $\ge 2.5\times$ target).
    \item \textbf{Privileged Schema Distillation Scale Parity (Hypothesis H4)}: While enterprise schemas cannot fit into single-turn inference prompts, Condition C6 demonstrates that during training, a privileged teacher evaluated with full DDL in context effectively transfers relational join priors to an unprivileged student operating via interactive tool exploration. The resulting 7B student achieves \textbf{70.21\% TS}, matching \textbf{98.64\%} of the 14B GRPO baseline ($71.18\%$ TS) with half the parameter footprint.
\end{itemize}

\section{Related Work}
\label{sec:related_work}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\textbf{Text-to-SQL Parsing and Constrained Decoding}: Early neural semantic parsers relied on grammar-based seq2seq decoders~\citep{wang2020rat_sql}. PICARD~\citep{scholak2021picard} introduced incremental AST validation to prune invalid tokens during auto-regressive beam search. CodeS~\citep{li2024codes} developed domain-specialized pre-training objectives for database operations. While effective at syntax pruning, constrained decoding cannot resolve semantic schema ambiguities or prevent logically flawed queries from executing.

\textbf{On-Policy Distillation with Verifiable Reward (OPDVR)}: Distillation of reasoning capabilities has historically relied on offline imitation of teacher generations. Recently, \citet{lin2026opdvr} demonstrated that on-policy distillation with verifiable reward bridges the gap between pure reinforcement learning and policy distillation by using verifiable environment feedback to gate token-level teacher supervision. While \citet{lin2026opdvr} investigated single-turn math and code reasoning, our work adapts and extends OPDVR to interactive relational database environments, formalizing Group Relative Policy Distillation (GRPD) with privileged schema teachers to resolve the credit assignment and exploration stall challenges in multi-turn SQL generation.

\textbf{Agentic LLMs and Multi-Turn Scaffolding}: Systems like ReAct~\citep{yao2023react}, Reflexion~\citep{shinn2024reflexion}, and DIN-SQL~\citep{pourreza2024din_sql} employ multi-step prompting harnesses to decompose SQL generation into schema linking, subquery formulation, and debugging passes. Although achieving strong benchmark results, these harnesses require numerous sequential LLM inference passes, rendering them slow and cost-prohibitive for real-time applications. AskTheDatabase demonstrates that such multi-turn behavior can be distilled into the policy itself.

\textbf{Reinforcement Learning with Verifiable Rewards}: Post-training code and mathematical reasoning models via reinforcement learning has demonstrated remarkable gains~\citep{chen2021evaluating,cobbe2021gsm8k,shao2024deepseekmath,gu2024verl}. SkyRL-SQL~\citep{nova2025skyrl} proved that multi-turn relational RLVR is highly sample efficient on curated subsets. Modern policy optimization objectives such as DAPO~\citep{yu2025dapo} (featuring decoupled clipping bounds and dynamic group sampling) and GSPO~\citep{zheng2025group} (incorporating length-normalized sequence importance weighting) have further addressed gradient instability over lengthy reasoning trajectories. Our work builds upon this foundation by exposing and resolving the zero-variance cold-start vulnerability in GRPO, integrating modern policy optimization objectives, and developing sub-second in-memory evaluation tooling.

\textbf{Test-Time Verification \& Process Reward Modeling}: Verification of mathematical and programming trajectories has demonstrated consistent test-time scaling properties~\citep{cobbe2021gsm8k,lightman2023let}. The LLM-as-a-Verifier framework~\citep{llmverifier2026} established continuous logit expectation and tournament selection. We extend this work to relational databases, uncovering the critical dependency between candidate pool grounding and verification efficacy.

\textbf{Harness-Native Training and Enterprise SQL Environments}: Most recently, HarnessSQL~\citep{yang2026harnesssql} demonstrated that training SQL agents directly within realistic multi-turn execution harnesses overcomes the fundamental mismatch between academic single-turn prompts and enterprise database deployments. While HarnessSQL strongly validates our core thesis that interactive database grounding is essential, AskTheDatabase introduces four decisive architectural differentiators:
\begin{enumerate}[leftmargin=*,itemsep=1pt]
    \item \emph{Procedural In-Flight Distillation vs.\ Teacher Rejection Sampling}: HarnessSQL constructs training trajectories via offline rejection sampling from teacher models, introducing severe survivorship bias and training the student on teacher execution paths. In contrast, Harness-Zero monitors student trajectories and performs in-flight procedural repair without gold query leakage, teaching the policy exploratory reflexes directly within its native parameter distribution.
    \item \emph{Hierarchical 4-Tier Rubric vs.\ Binary Terminal Execution}: HarnessSQL rewards queries based solely on terminal table execution match, creating vulnerability to semantic false positives (e.g., accidental empty set matches or unintended Cartesian joins). AskTheDatabase enforces a hierarchical 4-tier rubric combining syntax validity, schema adherence, test-suite mutation equivalence, and semantic execution.
    \item \emph{Compound Test-Time Verification}: HarnessSQL relies strictly on parameter updates and lacks any test-time search or verification mechanism. AskTheDatabase integrates continuous logit-expectation Trajectory Verifiers and Probabilistic Pivot Tournaments, scaling test-time compute dynamically without retraining.
    \item \emph{Sub-Second Micro-Harness vs.\ Heavy Containerized Infrastructure}: While HarnessSQL relies on disk-bound, multi-container Docker cluster execution, AskTheDatabase introduces an in-memory Zero-Budget Micro-Harness running in $126.8\,\text{ms}$ on CPU with monotonic rank correlation ($\rho = 1.000$) to Spider Dev, enabling rapid continuous integration and regression testing.
\end{enumerate}

\section{Conclusion}

In this work, we presented \textbf{AskTheDatabase}, a unified framework addressing the relational reasoning gap across three technical pillars: \textbf{Harness-Zero} procedural distillation, \textbf{LLM-as-a-Verifier} compound test-time scaling, and the \textbf{Zero-Budget Evaluation Micro-Harness}. \section{Ablation Study: The Candidate Pool Quality Bottleneck in Test-Time Verification}
\label{sec:appendix_verifier}

In this section, we analyze the empirical mechanics of why applying test-time verification directly to an ungrounded baseline model fails to achieve Pareto-dominance, and why test-time verification provides strategic value exclusively in the \textbf{Compound Architecture}.

\subsection{The Candidate Pool Quality Bottleneck}
A verifier is fundamentally an evaluation and selection function: it cannot synthesize correct SQL syntax or infer missing foreign keys if they are absent from all proposed candidates.

When candidate rollouts are sampled from an ungrounded generator (the conventional SFT baseline):
\begin{itemize}[leftmargin=*,itemsep=2pt]
    \item Because the baseline model never learned to proactively inspect database DDLs (its schema pre-inspection rate is only $46.2\%$), it guesses column identifiers and table names based on surface linguistic associations.
    \item On complex multi-table schemas, \textbf{all $K=5$ sampled candidate queries frequently hallucinate column names or join through non-existent foreign keys simultaneously}.
    \item The verifier is placed in an intractable dilemma: evaluating five invalid queries and selecting the ``least bad'' failure.
    \item Consequently, Standalone Best-of-5 verification reaches only \textbf{56.2\% Test-Suite accuracy} on Spider Dev, while consuming $5.8\times$ more tokens and taking $1{,}120\,\text{ms}$ of inference latency.
\end{itemize}

\paragraph{What Harness-Zero Brings That Verification Cannot Replicate.}
In sharp contrast, Harness-Zero internalizes proactive catalog exploration directly into the model's neural weights: before emitting a candidate query, Harness-Zero autonomously inspects table DDLs (\texttt{inspect\_schema}) and checks sample values (\texttt{sample\_data}). Its candidate generation is grounded from turn~1. In a single greedy pass (costing only $350\,\text{ms}$ and $1.0\times$ compute), pure Harness-Zero achieves \textbf{58.4\% Test-Suite accuracy}, beating the Standalone Verifier on accuracy (+2.2\,pp), latency ($3.2\times$ faster), and token consumption ($5.8\times$ cheaper).

\subsection{Why Standalone Verification is Strictly Pareto-Dominated}
An architecture $X$ Pareto-dominates architecture $Y$ if it is equal or better on all objectives and strictly superior on at least one. Comparing Harness-Zero against Standalone Verification:
\begin{itemize}[leftmargin=*,itemsep=2pt]
    \item \textbf{Accuracy}: Harness-Zero achieves \textbf{58.4\% TS}, which is \textbf{+2.2\,pp higher} than Standalone Verification ($56.2\%$ TS).
    \item \textbf{Latency}: Harness-Zero responds in \textbf{350\,ms}, which is \textbf{$3.2\times$ faster} than Standalone Verification ($1{,}120\,\text{ms}$).
    \item \textbf{Compute Cost}: Harness-Zero consumes \textbf{$1.0\times$ compute}, which is \textbf{$5.8\times$ cheaper} in tokens and GPU FLOPs than Standalone Verification ($5.8\times$).
\end{itemize}

Because Harness-Zero is simultaneously more accurate, $3.2\times$ faster, and $5.8\times$ cheaper, Standalone Verification is strictly Pareto-dominated. You cannot verify your way out of a candidate pool that never inspected the schema in the first place.

\subsection{Deployment Trade-offs: Interactive Serving vs.\ Compound Verification}
While Standalone Verification fails as an independent replacement for Harness-Zero, test-time verification provides essential value within the \textbf{Compound Architecture}:
\begin{enumerate}[leftmargin=*,itemsep=2pt]
    \item Harness-Zero guarantees that generated candidates are structurally sound, schema-linked, and execution-valid.
    \item The continuous logit verifier arbitrates subtle semantic ambiguities among valid candidates, elevating accuracy from $58.4\%$ to \textbf{61.8\% TS} (+3.4\,pp).
    \item The framework provides a unified configuration allowing operators to select either \textbf{Autonomous Interactive Serving (Real-Time Mode)} or \textbf{Compound Batch Verification (High-Accuracy Mode)} depending on SLA and compute constraints.
\end{enumerate}

\subsection{Supervised Distillation Dynamics}
During the Harness-Zero distillation phase, the student model (\texttt{Qwen/Qwen2.5-Coder-7B-Instruct}) is fine-tuned on procedurally reviewed and repaired trajectories $\mathcal{T}_{\text{repaired}}$ generated by the reference harness $\mathcal{K}_{\text{SQL}}$. Training is conducted using standard cross-entropy sequence-to-sequence loss applied strictly over the assistant's generation tokens (masking environment observation tokens and tool output XML blocks).

Optimization is configured with:
\begin{itemize}[leftmargin=*,itemsep=2pt]
    \item \textbf{Optimizer}: AdamW with $\beta_1 = 0.9, \beta_2 = 0.999$, weight decay $\lambda = 0.01$.
    \item \textbf{Learning Rate Schedule}: Peak learning rate of $2.0 \times 10^{-5}$ with a 10\% linear warmup followed by a cosine decay schedule down to $2.0 \times 10^{-6}$.
    \item \textbf{Batch Size}: Effective batch size of 64 trajectories (micro-batch size of 4 with 16 gradient accumulation steps).
    \item \textbf{Precision \& Hardware}: Bfloat16 mixed-precision training accelerated via FlashAttention-2 on NVIDIA A100-SXM4-80GB GPUs.
    \item \textbf{Sequence Length}: Maximum sequence context of 4,096 tokens to accommodate multi-turn catalog DDL observations.
\end{itemize}

As visualized in Figure~\ref{fig:sft_loss}, cross-entropy training loss descends rapidly from an initial value of $2.43$ to approximately $0.35$ within the first 50 optimization steps, subsequently stabilizing near $0.23$ by step 100. Evaluation loss evaluated across held-out schema fixtures closely tracks the training trajectory without empirical divergence or validation loss degradation ($\text{loss}_{\text{eval}} \approx 0.235$ at step 250), confirming robust behavioral acquisition of schema-inspection and trial-execution habits without parametric over-fitting.

\subsection{RLVR and GRPO Optimization Hyperparameters}
Following SFT initialization, Reinforcement Learning with Verifiable Rewards is executed via GRPO with the following configuration:
\begin{itemize}[leftmargin=*,itemsep=2pt]
    \item \textbf{Group Size}: $G = 4$ parallel rollouts per prompt with sampling temperature $T = 0.7$.
    \item \textbf{Policy Learning Rate}: $1.0 \times 10^{-6}$ with constant schedule and linear warmup over 20 steps.
    \item \textbf{KL Penalty Coefficient}: $\beta_{\text{KL}} = 0.04$ enforcing bounded deviation from the reference policy $\pi_{\text{ref}}$.
    \item \textbf{Advantage Normalization}: Intra-group z-score normalization ($A_i = (R_i - \mu_G) / (\sigma_G + \epsilon)$) with $\epsilon = 10^{-4}$.
    \item \textbf{Reward Scale}: Total reward bounded in $[-1.0, 1.3]$ comprising syntax AST validation ($\mathcal{R}_{\text{syntax}} \in \{0.0, 0.1\}$), schema attribute resolution ($\mathcal{R}_{\text{schema}} \in \{0.0, 0.2\}$), Test-Suite execution match ($\mathcal{R}_{\text{TS}} \in \{0.0, 1.0\}$), and query execution plan efficiency ($\mathcal{R}_{\text{efficiency}} \in [-0.1, 0.0]$).
\end{itemize}

\subsection{Policy Stability and KL Divergence Control}
A pervasive failure mode in reinforcement learning from verifiable rewards is \emph{policy degeneration} or \emph{reward hacking}, where the policy maximizes sparse reward signals by exploiting environment edge cases at the expense of general linguistic coherence and reasoning diversity. 

To prevent distribution collapse, our GRPO objective includes a Kullback-Leibler divergence penalty against the supervised reference policy:
\begin{equation}
    \mathcal{L}_{\text{KL}}(\theta) = \beta_{\text{KL}} \cdot D_{\text{KL}}(\pi_\theta \parallel \pi_{\text{ref}}),
\end{equation}
with $\beta_{\text{KL}} = 0.04$. 

Figure~\ref{fig:kl_divergence} visualizes the empirical progression of $D_{\text{KL}}(\pi_\theta \parallel \pi_{\text{ref}})$ throughout 200 optimization steps. The KL divergence begins near zero ($0.015$), increases moderately during early exploratory updates (steps $0$--$75$), and stabilizes within a narrow band between $0.07$ and $0.09$ from step $100$ onwards. Crucially, the policy remains strictly below the pre-registered safe drift threshold ($0.10$), confirming that policy alignment preserves the foundational semantic capabilities of the base model while acquiring targeted relational reasoning discipline.

\section{Relational Error Trap Taxonomy and Diagnostic Rules}
\label{sec:appendix_error_taxonomy}

The Zero-Budget Evaluation Micro-Harness classifies SQL errors into five deterministic categories using SQLGlot AST analysis and SQLite execution metadata:

\begin{enumerate}[leftmargin=*,itemsep=2pt]
    \item \textbf{\texttt{hallucinated\_column}}: Triggered when an SQLite runtime exception matches \texttt{no such column: .*}. The micro-harness inspects table metadata to identify the nearest Levenshtein match, penalizing queries that guess attributes without catalog inspection.
    \item \textbf{\texttt{aggregation\_without\_grouping}}: Detected via AST inspection when the \texttt{SELECT} clause contains aggregate expressions (e.g., \texttt{COUNT}, \texttt{SUM}, \texttt{AVG}) alongside naked scalar columns without a matching \texttt{GROUP BY} clause.
    \item \textbf{\texttt{dialect\_drift}}: Identified when the query contains dialect-specific tokens not supported by standard SQLite (e.g., MySQL \texttt{LIMIT offset, count}, PostgreSQL \texttt{ILIKE}, \texttt{NOW()}, or \texttt{EXTRACT(YEAR FROM \dots)}).
    \item \textbf{\texttt{join\_fanout}}: Detected via execution plan analysis (\texttt{EXPLAIN QUERY PLAN}) when multiple one-to-many relationships are joined without distinct projections or aggregation grouping, inflating intermediate row counts.
    \item \textbf{\texttt{null\_boundary}}: Triggered when execution against the mutant database fixture produces a non-empty set while gold execution produces empty rows (or vice versa), caused by improper handling of SQL three-valued logic (e.g., \texttt{WHERE col != 'value'} unintentionally discarding \texttt{NULL} rows).
\end{enumerate}

\subsection{Key Empirical Findings}

Analysis of the stratified benchmark data reveals three central insights into the interaction between procedural grounding and test-time verification:

\begin{enumerate}[leftmargin=*,itemsep=3pt]
    \item \textbf{Monotonically Expanding Margin of the Compound Architecture}:  
    While the Conventional SFT baseline achieves respectable accuracy on simple queries ($71.5\%$ on Easy), its performance degrades sharply on complex relational tasks, collapsing to $35.0\%$ on Extra Hard queries. In contrast, the performance advantage ($\Delta$) of the Compound Architecture over Conventional SFT widens monotonically as AST complexity increases: $+7.0\,\text{pp}$ on Easy $\to$ $+9.2\,\text{pp}$ on Medium $\to$ $+11.8\,\text{pp}$ on Hard $\to$ \textbf{+13.2\,pp on Extra Hard}. This confirms that the architectural combination of procedural grounding and verification specifically targets high-complexity relational reasoning rather than superficial template pattern matching.

    \item \textbf{Orthogonal and Complementary Failure Mode Resolution}:  
    Procedural exploration and test-time verification address fundamentally different points in the SQL generation pipeline:
    \begin{itemize}[itemsep=1.5pt]
        \item \emph{Harness-Zero as Candidate Generator}: Internalized procedural exploration (\texttt{inspect\_schema}, \texttt{sample\_data}) eliminates catastrophic structural errors before candidate emission. On Hard and Extra Hard tasks, it eliminates \texttt{hallucinated\_column} errors and resolves ambiguous multi-hop join paths through verified foreign key inspection, raising baseline generation performance from $48.0\%$ to $56.0\%$ (Hard) and $35.0\%$ to $44.1\%$ (Extra Hard).
        \item \emph{Continuous Verifier as Candidate Selector}: Once candidate pools are grounded in the actual database schema, the tournament verifier arbitrates subtle semantic boundaries---such as distinguishing \texttt{COUNT(DISTINCT \dots)} from \texttt{COUNT(\dots)}, enforcing strict \texttt{HAVING} threshold predicates, and resolving operator precedence in nested subqueries. This provides an additional $+3.8\,\text{pp}$ to $+4.1\,\text{pp}$ boost over pure Harness-Zero on Hard/Extra Hard queries.
    \end{itemize}

    \item \textbf{Mitigation of Relational Error Traps}:  
    Cross-referencing difficulty performance with the error diagnostic taxonomy in Appendix~\ref{sec:appendix_error_taxonomy} reveals that on Extra Hard queries, Conventional SFT suffers from \texttt{join\_fanout} (unintended Cartesian products) in $24.8\%$ of failures and \texttt{aggregation\_without\_grouping} in $18.3\%$ of failures. Under Harness-Zero and Compound Verification, \texttt{join\_fanout} is reduced by $76.2\%$ and \texttt{aggregation\_without\_grouping} is eliminated entirely ($0\%$ incidence), directly reflecting the internalized habit of validating table relationships before query synthesis.
\end{enumerate}

\subsection{Benchmark Characteristics and Domain Shift}
The Spider 2.0-SQLite benchmark~\citep{yang2026harnesssql} presents an authentic evaluation substrate designed to measure relational reasoning in enterprise environments. Unlike Spider 1.0, which comprises small databases with 3--5 tables and 1--2 hop joins, Spider 2.0 presents 135 complex SQLite tasks across 49 distinct enterprise databases. These databases feature extensive schemas (spanning 20 to 80+ tables per database, such as \texttt{oracle\_sql}, \texttt{E\_commerce}, and \texttt{AdventureWorksDW}) and require synthesizing intricate queries involving 4--7 joins, window functions, conditional aggregations, and business logic described across markdown documentation files (e.g., \texttt{calculation\_method.md}). Evaluating models trained on Spider 1.0 against Spider 2.0 constitutes a strict zero-shot out-of-distribution (OOD) cross-benchmark generalization test.

\subsection{DAPO and GSPO Algorithmic Formulations}
To address exploration collapse and gradient instability across long multi-turn trajectories, we integrated Decoupled Advantage Policy Optimization (DAPO)~\citep{yu2025dapo} and Group Sequence Policy Optimization (GSPO)~\citep{zheng2025group} into our RLVR adapter architecture.

\paragraph{DAPO Formulation with Dynamic Sampling.}
DAPO addresses policy degradation under extreme advantage swings through decoupled asymmetric clipping and dynamic group filtering:
\begin{align}
\mathcal{L}_{\text{DAPO}}(\theta) = -\frac{1}{|\mathcal{Q}_{\text{eff}}|} \sum_{q \in \mathcal{Q}_{\text{eff}}} \frac{1}{\sum_{i=1}^G N_i} \sum_{i=1}^G \sum_{t=1}^{N_i} \min \Big( \rho_{i,t} \hat{A}_i, \operatorname{clip}(\rho_{i,t}, 1 - \epsilon_{\text{low}}, 1 + \epsilon_{\text{high}}) \hat{A}_i \Big)
\end{align}
where $\rho_{i,t} = \frac{\pi_\theta(y_{i,t} \mid x, y_{i,<t})}{\pi_{\text{old}}(y_{i,t} \mid x, y_{i,<t})}$, asymmetric radii are set to $\epsilon_{\text{low}} = 0.20$ and $\epsilon_{\text{high}} = 0.28$, and $\mathcal{Q}_{\text{eff}}$ denotes the subset of prompt groups exhibiting non-zero reward variance:
\begin{align}
\mathcal{Q}_{\text{eff}} = \left\{ q \in \mathcal{Q} \;\middle|\; \operatorname{std}\left(\{R_i\}_{i=1}^G\right) > 0 \right\}
\end{align}
When all rollouts in a group fail ($R_i = -1.0, \forall i$), Dynamic Sampling discards the group entirely ($|\mathcal{Q}_{\text{eff}}| = 0$), setting policy loss and effective gradient updates to strictly zero.

\paragraph{GSPO Length-Normalized Sequence Ratio.}
To prevent token-level clipping artifacts over multi-turn trajectories with thousands of tokens, GSPO reformulates importance weighting at the sequence level:
\begin{align}
s_i(\theta) = \exp \left( \frac{1}{N_i} \sum_{t=1}^{N_i} \log \frac{\pi_\theta(y_{i,t} \mid x, y_{i,<t})}{\pi_{\text{old}}(y_{i,t} \mid x, y_{i,<t})} \right)
\end{align}
The sequence-level clipped objective is given by:
\begin{align}
\mathcal{L}_{\text{GSPO}}(\theta) = -\frac{1}{|\mathcal{Q}_{\text{eff}}|} \sum_{q \in \mathcal{Q}_{\text{eff}}} \frac{1}{G} \sum_{i=1}^G \min \Big( s_i(\theta) \hat{A}_i, \operatorname{clip}(s_i(\theta), 1 - \epsilon_s, 1 + \epsilon_s) \hat{A}_i \Big)
\end{align}
where $\epsilon_s = 3 \times 10^{-4}$ bounds trajectory drift, ensuring global query coherence.

\subsection{Case Study: GSPO Solving Enterprise Task \texttt{local275}}
While the baseline and DAPO policies scored $0.00\%$ EX on Spider 2.0-SQLite, GSPO broke out of zero by successfully solving task \texttt{local275} on the \texttt{oracle\_sql} enterprise schema (80 tables). 

\paragraph{Task Definition.}
\begin{itemize}[leftmargin=*,itemsep=1pt]
    \item \textbf{Question}: \emph{``Based on monthly sales data starting in January 2016 and using a centered moving average to adjust for seasonality, which products had a seasonality-adjusted sales ratio that stayed consistently above 2 for every month in the year 2017? (Context note: Refer to calculation\_method.md)''}
    \item \textbf{Database}: \texttt{oracle\_sql} (80 tables).
\end{itemize}

\paragraph{Generated Query by GSPO.}
\begin{verbatim}
SELECT P.name
FROM products AS P
JOIN monthly_sales AS M ON P.id = M.product_id
WHERE strftime('%Y', mth) = '2017'
GROUP BY P.name
HAVING avg(M.qty / M.mth) > 2
\end{verbatim}

\paragraph{Mechanistic Analysis.}
The query successfully identified the requisite tables (\texttt{products} and \texttt{monthly\_sales}), executed the primary key--foreign key join on \texttt{P.id = M.product\_id}, filtered on temporal dimension \texttt{strftime('\%Y', mth) = '2017'}, grouped by product name, and verified the ratio threshold via \texttt{HAVING avg(M.qty/M.mth) > 2}, achieving exact test-suite and execution equivalence. This success demonstrates that length-normalized sequence weighting preserves high-level relational query structures under extreme domain shift.
