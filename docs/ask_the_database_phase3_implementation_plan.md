# AskTheDatabase — Phase 3 Granular Implementation Plan
## SFT Warmup Pipeline & Framework Adapters (Issues #11 to #15)

---

## 1. Phase 3 Overview & Scientific Scope

The objective of **Phase 3** is to transition from environment engineering to **policy training**. Starting reinforcement learning directly from a raw base model (e.g., `Qwen2.5-Coder-7B-Instruct`) without an initial warmup phase leads to severe exploration collapse: the policy generates invalid tool-call syntax, hallucinated schemas, or random text, receiving $-1.0$ penalties on nearly 100% of initial rollouts.

Phase 3 establishes:
1. **The Framework Adapter Interface**: A clean abstraction barrier that decouples the policy optimization engine from the RL framework (SkyRL, veRL, NeMo RL, or TRL).
2. **Supervised Fine-Tuning (SFT) Warmup**: Fine-tuning the backbone model on curated text-to-SQL data (`SkyRL-SQL-653` + `Spider`) using QLoRA 4-bit/8-bit or bfloat16.
3. **TRL GRPO Adapter (Baseline Engine)**: A lightweight, single-turn Group Relative Policy Optimization adapter leveraging Hugging Face `trl` to verify reward gradients locally.
4. **The Portability Test Harness**: A 50-sample regression test that trains a small model (`Qwen2.5-Coder-1.5B`) to verify identical reward assignment and gradient updates across candidate frameworks.
5. **DVC Pipeline Stage Integration**: Embedding SFT and baseline training into `dvc.yaml` for deterministic cache tracking.

### Issue #11: Abstract Framework Adapter Interface

#### 1. Objectives & Responsibilities
- Implement `src/ask_the_database/training/adapters/base.py`.
- Define the contract that any RL training framework (SkyRL-Agent, veRL, TRL) must implement.
- Bridge between tensor-based token sequences produced by language models and the Python-based `SQLRewardRubric` from Phase 2.
- Provide standardized hooks for environment step transitions, reward calculation, and checkpoint saving.

#### 2. Exact File Contracts

##### `src/ask_the_database/training/adapters/base.py`
```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Any
from omegaconf import DictConfig
from ask_the_database.rewards.rubric import SQLRewardRubric


@dataclass(frozen=True)
class RolloutBatch:
    """Standardized batch of rollouts generated by an actor policy."""
    prompts: list[str]
    completions: list[str]
    gold_sqls: list[str]
    db_paths: list[str]
    metadata: list[dict[str, Any]]


class BaseRLAdapter(ABC):
    """Abstract interface isolating the RL engine from the SQL scientific core."""

    def __init__(self, config: DictConfig, rubric: SQLRewardRubric) -> None:
        self.cfg = config
        self.rubric = rubric

    @abstractmethod
    def initialize_models(self) -> None:
        """Initialize actor, critic (if applicable), and reference policy."""
        pass

    @abstractmethod
    def compute_rewards(self, batch: RolloutBatch) -> list[float]:
        """Compute scalar rewards for each completion in the batch using the rubric."""
        pass

    @abstractmethod
    def train_step(self, batch: RolloutBatch) -> dict[str, float]:
        """Execute policy optimization step and return telemetry metrics."""
        pass

    @abstractmethod
    def save_checkpoint(self, output_dir: str) -> None:
        """Persist policy weights and LoRA adapters."""
        pass
```

#### 3. Definition of Done & Verification Gate
Execute `mypy src/ask_the_database/training/adapters/base.py`:
- Interface passes strict type checking with zero abstract method ambiguities.

### Issue #13: TRL GRPO Adapter (Single-Turn Baseline)

#### 1. Objectives & Responsibilities
- Implement `src/ask_the_database/training/adapters/trl_grpo.py`.
- Implement Group Relative Policy Optimization (GRPO) using Hugging Face `trl.GRPOTrainer`.
- GRPO generates $G$ (default: $G=8$) completions per prompt, scores each completion using `SQLRewardRubric.evaluate()`, normalizes the rewards within the group (mean 0, std 1), and updates the policy without needing a separate critic (value network).
- Implement a custom reward callback function that unpacks generated completions, executes them against the SQLite database sandbox, and logs reward diagnostics to W&B.

#### 2. Exact File Contracts

##### `src/ask_the_database/training/adapters/trl_grpo.py`
```python
from typing import Any
import re
from omegaconf import DictConfig
from ask_the_database.rewards.rubric import SQLRewardRubric
from ask_the_database.training.adapters.base import BaseRLAdapter, RolloutBatch


def extract_sql_from_completion(text: str) -> str:
    """Extract SQL query from markdown code block or fallback to raw text."""
    match = re.search(r"```sql\s*(.*?)\s*```", text, re.DOTALL | re.IGNORECASE)
    if match:
        return match.group(1).strip()
    return text.strip()


class TRLGRPOAdapter(BaseRLAdapter):
    """TRL GRPOTrainer implementation of the RL adapter."""

    def __init__(self, config: DictConfig, rubric: SQLRewardRubric) -> None:
        super().__init__(config, rubric)

    def initialize_models(self) -> None:
        pass  # Handled inside GRPOTrainer initialization

    def compute_rewards(self, batch: RolloutBatch) -> list[float]:
        """Compute scalar rewards for each completion in the rollout batch."""
        rewards: list[float] = []
        for completion, gold_sql, db_path in zip(
            batch.completions, batch.gold_sqls, batch.db_paths, strict=True
        ):
            candidate_sql = extract_sql_from_completion(completion)
            out = self.rubric.evaluate(
                candidate_sql=candidate_sql,
                gold_sql=gold_sql,
                db_path=db_path,
            )
            rewards.append(out.total_reward)
        return rewards

    def train_step(self, batch: RolloutBatch) -> dict[str, float]:
        return {}

    def save_checkpoint(self, output_dir: str) -> None:
        pass
```

#### 3. Definition of Done & Verification Gate
Execute unit verification against mock completions:
- 8 completions evaluated across 1 prompt return 8 normalized scalar rewards reflecting exact execution match vs syntax error.

## 4. Phase 3 Summary & Transition to Phase 4

With Phase 3 complete:
- The SFT warm-up policy is fully trained and versioned in DVC at `models/sft/final`.
- The adapter layer (`BaseRLAdapter`) is established and tested.
- **Phase 4** will advance the model into an autonomous **Multi-Turn Database Agent** using the **SkyRL-Agent** ecosystem to perform multi-step database probing, data sampling, and iterative self-correction.
