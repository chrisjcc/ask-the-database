## 1. Executive Summary & Experimental Objectives

The goal of this experimental protocol is to empirically validate **OPDVR (On-Policy Distillation with Verifiable Reward)** and its group-relative extension **GRPD (Group Relative Policy Distillation)** within the **AskTheDatabase** multi-turn Text-to-SQL architecture.

Specifically, this study is designed to answer four empirical questions:
1. **Sample Efficiency**: Does token-level credit assignment via teacher log-ratios accelerate learning and achieve higher Test-Suite Accuracy ($\mathcal{R}_{\text{TS}}$) than outcome-level GRPO within a fixed compute budget?
2. **Exploration Plateau Elimination**: Does GRPD maintain meaningful policy gradient signals during the cold-start phase on hard queries where all rollouts fail ($\mathrm{std}(R) = 0$)?
3. **Preservation of Alternative Valid SQL**: Does the parameter-free ReLU gate protect semantically valid, syntactically novel queries from teacher distributional penalties compared to vanilla un-gated OPD?
4. **Privileged Schema Distillation**: Can an unprivileged student operating via zero-knowledge tool retrieval effectively absorb relational join priors from a privileged teacher provided with full DDL in context?

* **Hypothesis 1 (Credit Assignment Acceleration)**:
  In multi-turn episodes with up to 5 tool interactions ($500 - 1,500$ tokens), dense token rewards generated by GRPD will guide the model toward correct join conditions and valid projections significantly faster than sparse trajectory rewards.
  *Success Threshold*: Condition C4 (GRPD) achieves $\ge 4.0\,\text{pp}$ higher Test-Suite Accuracy than Condition C1 (GRPO) at training step 100.
* **Hypothesis 2 (Exploration Stall Elimination)**:
  On the "Extra Hard" subset of Spider (queries requiring complex subqueries and $\ge 3$ joins), where initial rollout pass rates are near zero ($\text{Pass@}4 = 0$), the GRPD token reward remains active via $-\mathrm{ReLU}(\log(\pi_\theta / \pi_T))$, suppressing hallucinated column names and keeping gradient norms $> 0.05$.
  *Success Threshold*: Zero-variance gradient freeze duration drops from 27 consecutive steps to $< 5$ steps.
* **Hypothesis 3 (Preservation of Alternative SQL Formulations)**:
  Vanilla OPD (Condition C2) forces the student to mimic the exact syntax of the teacher, depressing passing queries that use valid CTEs instead of inline subqueries. GRPD's ReLU gate zeros out penalties on all verified correct trajectories ($\pi_\theta > \pi_T$).
  *Success Threshold*: GRPD achieves $\ge 2.5\times$ higher AST structural variety (measured by SQLGlot AST hash entropy) on correct queries compared to vanilla OPD.
* **Hypothesis 4 (Privileged Teacher Knowledge Transfer)**:
  A privileged teacher (Qwen2.5-Coder-7B with full DDL in context) can supervise an unprivileged student (Qwen2.5-Coder-7B with zero-knowledge tool retrieval), allowing the student to achieve task success parity with a model twice its size.
  *Success Threshold*: The unprivileged 7B student trained with privileged GRPD achieves $\ge 98\%$ of the TS accuracy of a full 14B model trained with standard GRPO.

## 3. Experimental Matrix & Benchmark Environments

### 3.1 Benchmark Datasets
1. **Spider 1.0 Development Split**:
   - Complete evaluation set: 1,034 queries across 20 distinct relational databases.
   - Evaluates cross-domain generalization under strict zero-knowledge schema exploration.
2. **Spider 2.0-SQLite Subset** (Enterprise Validation):
   - 135 complex enterprise tasks derived from Spider 2.0-DBT and SQLite migrations.
   - Characterized by massive multi-table schemas ($> 20$ tables) where full DDL cannot fit in standard context windows.

### 3.2 Controlled Experimental Conditions

The proof-of-concept will benchmark seven strictly controlled conditions under identical training budgets, seeds, and hardware configurations:

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                 EXPERIMENTAL MATRIX (7 CONDITIONS)                               │
├────┬──────────────────┬─────────────────┬──────────────────────┬─────────────────────────────────┤
│ ID │ Condition Name   │ Base Model      │ Policy Optimization  │ Supervisory Signal              │
├────┼──────────────────┼─────────────────┼──────────────────────┼─────────────────────────────────┤
│ C0 │ SFT Baseline     │ Qwen2.5-Coder-7B│ Offline SFT          │ Harness-Zero Procedural Corpus  │
│ C1 │ Pure RLVR (GRPO) │ C0 Checkpoint   │ GRPO (Group Size 4)  │ Verifiable Mutation R_TS        │
│ C2 │ Vanilla OPD+GRPO │ C0 Checkpoint   │ Un-Gated OPD + GRPO  │ R_TS + Un-gated Sampled OPD     │
│ C3 │ Binary OPDVR     │ C0 Checkpoint   │ Binary OPDVR (REINF) │ Binary R \in {-1, +1} + ReLU    │
│ C4 │ Full GRPD (Ours) │ C0 Checkpoint   │ GRPD (Group Size 4)  │ Group Adv \hat{A}_i + ReLU Gate │
│ C5 │ Inv-GRPD (Abl)   │ C0 Checkpoint   │ Inverted GRPD        │ Swapped ReLU Gates (Neg Control)│
│ C6 │ Privileged GRPD  │ C0 Checkpoint   │ GRPD (Group Size 4)  │ Privileged Teacher (Full DDL)   │
└────┴──────────────────┴─────────────────┴──────────────────────┴─────────────────────────────────┘
```

#### Detailed Specification of Conditions:
* **C0 (SFT Baseline)**: Standard supervised fine-tuning initialized with the Harness-Zero procedural dataset. No reinforcement learning.
* **C1 (Pure RLVR Baseline)**: Standard multi-turn GRPO with group size $G = 4$. Trajectory reward is computed via AskTheDatabase's 4-tier mutation verifier ($\mathcal{R}_{\text{total}}$). Token advantage is uniform across all tokens in the trajectory.
* **C2 (Vanilla OPD+GRPO Baseline)**: Direct linear combination of sampled-token OPD and GRPO ($\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{GRPO}} + 1.0 \cdot \mathcal{L}_{\text{OPD}}$) without gating (following Xiao et al., 2026).
* **C3 (Binary OPDVR)**: OPDVR with REINFORCE-style binary outcome gating: $R_{\text{OPDVR}} = R \cdot \mathrm{ReLU}(R \cdot \log(\pi_T / \pi_\theta))$, where $R = +1$ if $\mathcal{R}_{\text{TS}} = 1.0$, and $R = -1$ if $\mathcal{R}_{\text{TS}} = 0.0$.
* **C4 (Full GRPD - Primary Target)**: Group Relative Policy Distillation using group advantage $\hat{A}_i$ to scale the sign-aligned ReLU gate: $R_{\text{GRPD}} = \hat{A}_i \cdot \mathrm{ReLU}(\mathrm{sign}(\hat{A}_i) \cdot \log(\pi_T / \pi_\theta))$. Same-architecture unprivileged teacher.
* **C5 (Inverse-Gated Negative Control)**: Reverses the ReLU gates: keeps tokens where $\pi_\theta > \pi_T$ on correct trajectories, and tokens where $\pi_T > \pi_\theta$ on incorrect trajectories. Designed to confirm that the performance gains of C4 originate from conflict removal rather than arbitrary token filtering.
* **C6 (Privileged Teacher GRPD)**: Same optimization as C4, but the teacher model $\pi_T$ is provided with the full flattened DDL schema in its prompt during token scoring.

## 4. Evaluation Protocol & Diagnostics

### 4.1 Primary Evaluation Metrics
1. **Test-Suite Mutation Accuracy ($\mathcal{R}_{\text{TS}}$)**:
   $$\mathcal{R}_{\text{TS}} = \frac{1}{N} \sum_{n=1}^N \prod_{k=0}^K \mathbb{I}\left( Q_{\text{gen}}^{(n)}(\mathcal{D}_k) \equiv Q_{\text{gold}}^{(n)}(\mathcal{D}_k) \right)$$
   Evaluated across $K = 5$ perturbed SQLite databases. Gold standard preventing false-positive table matches.
2. **Execution Accuracy (EX)**: Classical evaluation on the original unperturbed database instance $\mathcal{D}_0$.
3. **Difficulty Stratification**: Breakdown of $\mathcal{R}_{\text{TS}}$ across Spider difficulty tiers: Easy, Medium, Hard, and Extra Hard.

### 4.2 Training Dynamics & Diagnostic Telemetry
To monitor the microscopic mechanics of OPDVR, the training engine will log the following diagnostic variables at every optimization step:
* **Zero-Gated Token Ratio ($r_{\text{zero}}$)**:
  $$r_{\text{zero}} = \frac{\sum_{t \in \mathcal{I}_{\text{active}}} \mathbb{I}\left( R_{\text{GRPD}}(x_t) = 0 \right)}{|\mathcal{I}_{\text{active}}|}$$
  Tracks the fraction of tokens whose updates are masked out by the ReLU gate. We verify that $r_{\text{zero}}$ remains stably bounded within the theoretical $40\% - 50\%$ band throughout training.
* **Type I vs. Type II Conflict Rate**:
  - Fraction of tokens on correct trajectories zeroed due to student confidence ($\pi_\theta > \pi_T$).
  - Fraction of tokens on incorrect trajectories zeroed due to teacher confidence ($\pi_T > \pi_\theta$).
* **Effective Policy Gradient Norm ($\|\nabla_\theta \mathcal{L}\|$)**: Verifies that gradient signals do not collapse to zero during plateau episodes.
* **Tool Interaction Efficiency**:
  - Average interaction turns per query ($T_{\text{avg}}$).
  - Tool execution error rate (percentage of `execute_sql` calls returning SQLite operational errors).

## 5. Hyperparameters & Compute Resource Plan

### 5.1 Training Hyperparameters

| Hyperparameter | Value | Rationale |
| :--- | :--- | :--- |
| **Base Model / Student** | `Qwen/Qwen2.5-Coder-7B-Instruct` | SOTA open-weights code model with strong SQL foundation |
| **Teacher Model (C2–C5)**| `Qwen/Qwen2.5-Coder-7B-Instruct` (Frozen base) | Weight-shared base architecture; 0 MB additional param VRAM |
| **Privileged Teacher (C6)**| `Qwen/Qwen2.5-Coder-7B-Instruct` + Full DDL | Privileged context injection |
| **PEFT Method** | LoRA ($r = 16, \alpha = 32, \text{dropout} = 0.05$) | Validated by AskTheDatabase PR #100 |
| **Target Modules** | `all-linear` | Adapts all attention and MLP projection layers |
| **Group Size ($G$)** | 4 | 4 rollouts per prompt balance diversity and memory |
| **Learning Rate** | $5 \times 10^{-6}$ (with Cosine Decay) | Stable policy gradient updates |
| **Max Multi-Turn Turns** | 5 turns | Sufficient for schema discovery and dry-run testing |
| **Max Context Length** | 4,096 tokens | Accommodates multi-turn interaction traces |
| **Sandbox Timeout** | 10.0 seconds | Enforces bounded trial SQL execution |
| **Optimizer** | AdamW ($\beta_1 = 0.9, \beta_2 = 0.95, \text{wd} = 0.01$) | Standard RLVR optimization settings |

### 5.2 Compute Resource Budget
* **Hardware Requirement**: $1 \times \text{NVIDIA A100 (80GB)}$ or $2 \times \text{RTX 4090 (24GB)}$.
* **LoRA Weight Sharing**: Because student and teacher share the identical base 7B model weights, only one copy of the 7B parameters is resident in GPU VRAM ($\approx 14\,\text{GB}$ in bfloat16).
* **Rollout Throughput**: Using SkyRL and Hugging Face PEFT, rollout generation runs at $\approx 85\,\text{tokens/sec}$. An evaluation step over 100 training steps requires $\approx 3.5$ GPU hours on an A100-80GB.
